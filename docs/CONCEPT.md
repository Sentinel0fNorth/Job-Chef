# CONCEPT: The Offline-First Agentic Job Matcher
**Version:** 1.0 (Finalized Foundation)
**Document Purpose:** To provide human developers and AI engineering agents with the high-level philosophy, non-functional goals, constraints, and business logic driving this application.

## 1. The Manifesto (What & Why)
The "Agentic Job Matcher" is not a standard job board aggregator. It is a highly specialized, personalized career-tech platform built for high-intent job seekers (specifically in the Software Engineering domain). 

It solves the modern "application fatigue" problem by decoupling the discovery phase from the tailoring phase. It allows users to browse curated, highly relevant job listings in a rapid, tactile mobile interface, and delegates the tedious work of customizing resumes and cover letters to a cloud-native AI worker.

## 2. Core Philosophies (The Guardrails)
AI Agents and developers working on this project MUST adhere to these three pillars:

* **The "Zero-Cost" OPEX Shield:** The system architecture is aggressively optimized to cost $0 to operate. Every external API (Adzuna, Gemini) has strict free-tier limits. The codebase must prioritize deterministic local computing (e.g., Java string matching) over generative AI for simple tasks, relying on caching, rate-limiting, and Just-In-Time (JIT) execution to protect quotas.
* **Offline-First & Tactile:** The Android client must not feel like a web wrapper. It uses local Jetpack Compose state management and a Room Database to ensure that swiping, reading, and organizing jobs works flawlessly even with zero network connectivity.
* **"Hybrid Tech-Luxury" Aesthetic:** The UI completely rejects standard "startup app" aesthetics. It blends a warm, "Quiet Luxury" reading environment (creams, beiges, serif fonts) with a high-tech "Boardroom Slate" glassmorphic interface for active swiping and AI execution. It signals precision, trust, and professional authority.

## 3. The Feature Lifecycle (The Golden Path)
The architecture follows a strict, unidirectional flow to preserve resources:
1. **Ingest & Extract (Deterministic):** The Spring Boot backend fetches raw data from the Adzuna API. Instead of using AI, the backend uses hardcoded Java `HashSet` dictionaries to instantly extract "Skills" and "Work Mode" (Remote/Hybrid) in milliseconds.
2. **Curated Batching (UX):** The app explicitly rejects "Infinite Scroll." The backend delivers a finite batch of 15-20 jobs. A segmented progress bar forces intentional swiping, preventing mindless API token burn.
3. **The JIT AI Trigger (Generative):** The Gemini 1.5 Flash AI is *only* invoked when a user swipes right (`SAVED`). This background Pub/Sub event ensures the heaviest compute task is executed only for high-intent opportunities.
4. **Export:** The final output is an ATS-compliant, structurally perfect LaTeX PDF generated by the backend and synced to the mobile device.

## 4. Key Constraints & Complexities

### The Technical Challenges
* **Java Cold Starts:** Standard Spring Boot takes seconds to boot. To maintain our $0 Cloud Run budget without complex GraalVM pipelines, we rely entirely on GCP's "Startup CPU Boost" to handle JVM latency.
* **Schema Drift:** Keeping the PostgreSQL `JSONB` schema aligned with the Android Room database entities and the Gemini JSON output requires strict typing.
* **Data Sanitization:** Resumes contain Personally Identifiable Information (PII). Client-side Regex masking must execute before *any* data is transmitted over the network.

### The Scope Freezes (What we are NOT building)
To prevent "feature creep" and ensure a polished V1 release, the following are explicitly out of scope:
* **Universal URL Scraping:** We rely purely on the structured Adzuna API. Scraping LinkedIn, Indeed, or Greenhouse URLs is fragile and blocked by Cloudflare. 
* **In-App Messaging/Interviews:** This is a tailoring pipeline, not a social network.
* **Multiple Job APIs:** While Jooble or Talroo were considered, V1 locks into Adzuna for the best developer experience and structured JSON.

## 5. Strategic Benefits (The Portfolio Impact)
For the system architect (the creator), this project is designed to demonstrate:
1. **Enterprise Resource Management:** Proving the ability to design cost-aware, rate-limited systems.
2. **Event-Driven Microservices:** Showing mastery of asynchronous message brokers (Pub/Sub) to decouple heavy processing from UI threads.
3. **Native Mobile Hardware:** Utilizing tactile Compose gestures and local Room databases over generic web views.
4. **Agentic AI Integration:** Moving beyond basic "chatbot" API calls into structured, pipeline-driven AI document generation.
